# Pocket Lock

휴대폰이 주머니에 들어간 상태를 감지해 Android 시스템 잠금을 요청하는 Android 앱입니다. 근접 센서의 신뢰도를 확인해 근접 센서 방식 또는 복합 센서 방식을 사용합니다.

## 현재 기능

- `내 휴대폰에 맞게 자동 설정` 테스트에서 근접 센서가 정상 동작하면 근접 센서 방식, 센서가 없거나 신뢰할 수 없으면 복합 센서 방식으로 전환
- 근접 센서 방식은 기본 모드에서 세로로 뒤집힌 상태로 센서가 약 0.5초 가려지면 잠금
- 민감 모드는 근접 센서 방식에서 방향과 관계없이 센서가 약 0.3초 가려지면 잠금
- 복합 센서 방식은 사용 가능한 경우 조도 변화, 가속도계 움직임 및 자세를 함께 확인
- 조도 센서가 없는 기기에서는 평상시 자세에서 주머니 방향 자세로 바뀌는 움직임과 자세가 유지되는지 확인
- 근접 센서 민감도를 `보통`과 `민감` 중에서 선택
- `민감` 선택 시 사용 중인 화면이 근접 센서에 의해 닫힐 수 있다는 확인 메시지 표시
- 같은 가림 상태에서는 중복 잠금을 방지
- 포그라운드 서비스로 백그라운드에서 센서 감시
- Android 9(API 28) 이상은 동의 후 접근성 서비스의 시스템 잠금 동작 사용
- Android 8.1(API 27) 이하는 Device Admin의 `lockNow()` 사용
- `기기 진단` 화면에서 해당 OS의 잠금 권한, 센서 및 화면 잠금 상태를 확인
- 메인 화면 오른쪽 위의 `사용 방법` 버튼에서 상세 앱 사용 설명 확인
- 진단 화면의 `화면 잠금 테스트` 버튼으로 OS 버전에 맞는 잠금 요청을 별도로 확인
- 진단 결과를 클립보드에 복사
- Pocket Lock 전용 런처 아이콘 제공
- 앱 화면의 `앱 삭제 준비` 버튼으로 필요한 권한 해제 또는 앱 정보 화면으로 이동

## 기기 진단

메인 화면에서 `기기 진단`을 누르면 진단 화면으로 이동합니다. 진단 화면의 뒤로가기 버튼으로 메인 화면으로 돌아올 수 있습니다.

다음 정보를 표 형태로 확인할 수 있습니다.

- 기기 정보: 제조사, 모델, Android 버전, SDK 버전
- Android 9 이상: 앱 내 동의, 접근성 설정 활성화 및 서비스 연결 상태
- Android 8.1 이하: 현재 Device Admin 권한 활성화 여부
- 근접 센서: 센서 존재 여부, 이벤트 수신 여부, 이름, 제조사, 최대 범위, 해상도, 전력, 현재값, 이벤트 횟수, 최근 이벤트 시각, `StringType`, Wake-up 여부, Reporting Mode
- 가속도 센서: 센서 존재 여부, 이름, X/Y/Z 현재값, 이벤트 횟수, 최근 이벤트 시각
- 조도 센서: 센서 존재 여부, 이름, 현재 조도값, 이벤트 횟수, 최근 이벤트 시각

근접 센서가 있으면 진단 화면에서 센서값과 이벤트를 확인할 수 있습니다. 센서가 없거나 이벤트가 전달되지 않아도 앱이 종료되지 않고 `감지되지 않음` 또는 `이벤트 없음` 상태를 표시합니다. 메인 화면의 `내 휴대폰에 맞게 자동 설정` 테스트 또는 진단 화면의 근접 센서 테스트 결과에 따라 신뢰할 수 없는 센서는 복합 센서 방식으로 전환합니다.

진단 화면의 `화면 잠금 테스트`는 주머니 감지 알고리즘을 거치지 않고 현재 Android 버전에서 필요한 권한을 확인한 뒤 화면 잠금을 요청합니다. Android 9 이상에서는 접근성 서비스가 연결되어야 하며, Android 8.1 이하는 Device Admin 권한을 확인합니다.

1. 해당 Android 버전의 화면 잠금 권한과 접근성 서비스 연결이 정상인지
2. 근접 센서가 존재하는지
3. 근접 센서 이벤트가 실제로 전달되는지
4. 가속도 센서 이벤트가 전달되는지
5. Android의 화면 잠금 요청이 동작하는지

`진단 결과 복사`를 누르면 제조사, 모델, Android/SDK 버전, 센서 정보와 이벤트 상태가 클립보드에 복사됩니다. 전화번호, IMEI, Android ID, 광고 ID, 계정, 이메일, 위치, Wi-Fi, MAC 주소, IP 주소 등 개인정보나 식별 정보는 포함하지 않습니다.

진단 화면의 센서 Listener는 해당 화면이 표시되는 동안에만 등록되며, 화면을 벗어나면 해제됩니다. 주머니 잠금 감시는 사용자가 기능을 켠 동안 포그라운드 서비스에서 수행됩니다.

근접 센서가 없거나 신뢰할 수 없는 기기에서는 복합 센서 방식이 사용됩니다. 조도 센서가 없더라도 가속도계가 있으면 자세 변화와 움직임을 이용해 주머니 삽입을 감지합니다. 기종별 센서 동작이 다를 수 있으므로 문제가 있으면 진단 결과를 확인해 지원 시 공유해 주세요.

## 필요한 권한

Android 9 이상에서는 앱 내 권한 안내에 동의한 다음 접근성 설정에서 Pocket Lock 서비스를 직접 켜야 합니다. 이 서비스는 주머니 감지 조건을 만족했을 때 Android 화면 잠금 동작만 요청하며, 다른 앱의 화면·입력 정보를 읽거나 접근성 이벤트를 수집하지 않습니다. 동의는 서비스 활성화를 대신하지 않습니다.

Android 8.1 이하에서는 기존 Device Admin 방식으로 잠급니다. 이 방식은 Android 보안 정책에 따라 잠금 후 지문·얼굴 대신 PIN·패턴·비밀번호를 요구할 수 있습니다.

앱을 처음 사용할 때 권한을 설정한 뒤 `주머니 잠금 켜기`를 활성화합니다. Android 9 이상에서는 접근성 설정 활성화도 사용자가 직접 완료해야 합니다.

Android 13 이상에서 알림 권한을 요청하면 허용해야 포그라운드 서비스 알림을 정상적으로 표시할 수 있습니다.

## 사용 방법

1. 메인 화면에서 `내 휴대폰에 맞게 자동 설정`을 실행해 근접 센서를 가렸다가 노출합니다.
2. 근접 센서가 신뢰 가능하면 근접 센서 방식, 센서가 없거나 신뢰할 수 없으면 복합 센서 방식이 선택됩니다.
3. 복합 센서 방식에서는 휴대폰을 세로로 뒤집어 주머니에 넣습니다. 조도 센서가 있으면 조도 변화도 감지에 이용하고, 조도 센서가 없어도 가속도계가 지원되면 자세와 움직임으로 감지합니다.
4. PIN, 패턴, 비밀번호 또는 생체 인증 등 휴대폰의 기본 방식으로 잠금을 해제합니다.

화면 잠금 자체만 테스트하려면 메인 화면의 `기기 진단` → `화면 잠금 테스트`를 사용합니다. 필요한 권한이나 접근성 서비스 연결이 없으면 진단 화면에 상태가 표시됩니다.

## 빌드 및 설치

### Android Studio

1. Android Studio에서 이 폴더를 엽니다.
2. Gradle Sync가 완료될 때까지 기다립니다.
3. USB 디버깅을 활성화한 Android 휴대폰을 연결합니다.
4. 휴대폰에서 USB 디버깅 허용을 승인합니다.
5. 상단 기기 목록에서 휴대폰을 선택하고 Run을 누릅니다.

### VS Code 터미널

JDK 17과 Android SDK가 설치되어 있고 `local.properties`가 올바른 SDK 경로를 가리키는지 확인합니다.

```powershell
$env:JAVA_HOME = "C:\\Program Files\\Eclipse Adoptium\\jdk-17.0.20.8-hotspot"
.\gradlew.bat :app:assembleDebug
```

생성된 APK는 다음 위치에 있습니다.

```text
app/build/outputs/apk/debug/app-debug.apk
```

ADB로 연결된 휴대폰에 직접 설치할 수도 있습니다.

```powershell
adb devices
adb install -r .\app\build\outputs\apk\debug\app-debug.apk
```

## Google Play 출시용 AAB

Play Console에 업로드하려면 앱 번들을 릴리스 키로 서명해야 합니다. 업로드 키는 한 번 생성한 뒤 안전하게 백업하고 저장소에는 올리지 않습니다.

```powershell
keytool -genkeypair -v -keystore pocket-lock-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias pocket-lock-upload
```

프로젝트 루트의 `keystore.properties`에 다음 값을 입력합니다. `storeFile`은 키 파일의 절대 경로를 사용합니다.

```properties
storeFile=C:/secure/path/pocket-lock-upload.jks
storePassword=KEYSTORE_PASSWORD
keyAlias=pocket-lock-upload
keyPassword=KEY_PASSWORD
```

그 다음 릴리스 번들을 생성합니다.

```powershell
.\gradlew.bat :app:bundleRelease
```

생성 파일은 `app/build/outputs/bundle/release/app-release.aab`입니다.

휴대폰이 `adb devices`에 표시되지 않으면 USB 디버깅, USB 케이블, 연결 모드 및 제조사 USB 드라이버를 확인합니다.

## 앱 삭제

`앱 삭제 준비`를 누릅니다. 기존 Device Admin 권한이 활성화된 경우 해제 화면으로 이동합니다. Android 9 이상에서 접근성 서비스가 켜져 있으면 이를 끄는 설정이나 앱 정보 화면을 선택할 수 있습니다. 일반적으로 접근성 서비스를 끄지 않아도 앱을 삭제할 수 있습니다.

## Android 보안상 제한

- 근접 센서를 사용할 수 없거나 신뢰할 수 없는 경우 복합 센서 방식으로 전환됩니다. 가속도계도 사용할 수 없는 기기에서는 주머니 감지가 동작하지 않습니다.
- Android 8.1 이하의 Device Admin 잠금은 Android 보안 정책에 따라 생체 인증 대신 PIN·패턴·비밀번호 입력을 요구할 수 있습니다.
- Android 9 이상의 접근성 잠금 후 생체 인증 지원 여부는 제조사와 Android 보안 정책에 따라 달라질 수 있으므로 실제 기기에서 확인해야 합니다.
- Android 9 이상에서는 접근성 서비스가 비활성화되거나 연결되지 않으면 잠금을 요청하지 않으며 Device Admin 방식으로 자동 전환하지 않습니다.
- Pocket Lock에는 `FLAG_SECURE` 또는 `setScreenCaptureDisabled()`를 이용한 화면 캡처 차단이 없습니다. 제조사별 캡처 동작은 실제 기기에서 확인해야 합니다.
- 일반 앱은 볼륨 키 두 번 같은 방식으로 시스템 잠금을 해제할 수 없습니다.
- 화면이 켜진 채로 주머니 속 터치만 전역 차단하는 기능은 일반 앱 권한으로 보장할 수 없습니다.
- 카카오톡 등 알림이 오면 Android 설정에 따라 잠금 화면이 잠시 켜질 수 있습니다. 일반 앱은 다른 앱의 알림이 화면을 깨우는 것을 강제로 차단할 수 없으므로, 완전히 어둡게 유지하려면 휴대폰 설정에서 잠금 화면 알림 표시와 알림에 의한 화면 켜기를 끄거나 방해 금지 모드를 사용해야 합니다.
- `두 번 탭하여 화면 켜기`, `들어서 화면 켜기`, 알림에 의한 화면 켜기, Smart Lock은 휴대폰 설정에 따라 별도로 조정해야 합니다.
- 런처 아이콘은 앱 목록에 등록됩니다. Android는 일반 앱 설치 시 홈 화면에 아이콘을 자동 배치하는 것을 보장하지 않으므로, 필요하면 앱 목록에서 아이콘을 홈 화면으로 추가합니다.

## Google Play 접근성 서비스 제출

Pocket Lock은 장애인 지원용 접근성 도구가 아니므로 `isAccessibilityTool`을 `true`로 선언하지 않습니다. Play Console에서 AccessibilityService API 선언을 제출하고, 실제 사용 목적에 맞게 응답해야 합니다. 선언 검토를 통과한다고 보장할 수 없습니다.

제출 영상에는 앱 실행, 앱 안의 별도 권한 안내와 동의, 동의 취소 흐름, Android 접근성 설정에서 사용자가 직접 서비스를 켜는 흐름, 주머니 감지 후 화면 잠금 기능을 포함합니다. 접근성 서비스 사용 방식이 명확히 보이도록 캡션이나 설명을 넣습니다.

공식 안내: [Google Play AccessibilityService API 정책](https://support.google.com/googleplay/android-developer/answer/10964491)
